# RW Balance 样式表与 Tailwind CSS 整改建议

> 文档状态：第 4、5、6 部分已完成（2026-09-13 复核；真实设备与 Firefox 验收仍单列在第 8 部分）
> 形成日期：2026-09-13
> 适用范围：`src/App.vue`、`src/components/`、`src/styles/`、Vite/Tailwind 构建配置及样式相关测试

## 1. 整改背景

项目需求规格说明书在技术栈章节中明确约束“样式：Tailwind CSS”，项目目录大纲也将 `src/styles/` 定义为 Tailwind CSS 入口、基础样式和主题变量的存放位置。

当前实现虽然已经安装 Tailwind CSS 4、接入 `@tailwindcss/vite` 并在 `main.css` 中导入 Tailwind，但页面布局、间距、排版、颜色、交互状态和响应式规则几乎全部由手写全局 CSS 完成。Tailwind 目前主要停留在“进入构建管线”的层面，未成为实际的样式实现方式，因此不能视为已经完整满足技术栈约束。

整改前的样式实现还有以下客观特征：

- `src/App.vue` 约 1366 行，承载绝大多数页面模板和交互。
- `src/styles/main.css` 约 687 行、71 KB，包含主题变量、基础重置、组件样式、页面样式、动画和全部断点。
- 大量无命名空间的全局选择器依赖文件顺序和选择器优先级工作。
- Tailwind 扫描模板后会生成 `.grid` 等工具类，已经与统计 SVG 的语义类名发生碰撞。
- 样式中存在未定义变量、重复断点、后置覆盖和移动端适配风险。

本次整改的目标不是机械地把每条 CSS 都改写成工具类，而是使 Tailwind CSS 真正承担常规 UI 样式职责，同时保留确实适合使用原生 CSS 的主题变量、关键帧、复杂伪元素和 SVG 样式。

## 2. 修改建议清单（按页面实际布局影响分类）

本分类描述的是实施时对页面几何布局产生变化的可能性，不代表事项的重要程度。“基本不影响布局”的缺陷仍可能影响颜色、交互反馈、离线能力或工程合规性，也可能具有较高修复优先级。

页面实际布局包括元素尺寸、位置、换行、滚动、断点切换、遮挡关系和可视区域；仅改变颜色、光标、动画时长、检查流程或文档状态的事项归入“基本不影响布局”。

- [x] **L-10 基础组件与页面拆分**：登录、总览、账户、标签、账目、统计、设置均已拆为页面组件；Modal、账户表单、标签向导、账目录入、主题与数据迁移流程已拆为独立组件。

- [ ] **L-12 布局回归测试（部分完成）**：已自动覆盖 320、375、768、1024、1440px、底栏遮挡、六列表格横向滚动、键盘展开和 200% 字体；真实 iPhone 独立 PWA、横屏与软键盘仍需设备或 CI 验收。

### B. 基本不会影响页面实际布局的修改项

- [x] **N-01 危险色令牌修复**：定义亮色和暗色主题下的 `--rw-color-danger-soft`，恢复浏览器能力警告及“移除待添加标签”按钮的背景色。
- [x] **N-02 设计令牌清理**：检查未使用的颜色、图表饱和度和 Surface 变量；删除无消费者的令牌或补充明确用途。
- [x] **N-03 普通禁用态反馈修正**：将普通禁用按钮的 `cursor: wait` 改为 `not-allowed` 或默认光标，仅在真实异步处理中显示等待状态。
- [x] **N-04 焦点可见性统一**：为交互控件补充一致的 `focus-visible` 外观，并保持焦点样式不改变元素占位尺寸。
- [x] **N-05 低动画规则合并**：合并重复的 `prefers-reduced-motion` 定义，使 Tailwind 动画和保留的自定义关键帧遵循同一策略。
- [x] **N-06 原生 CSS 职责整理**：将主题变量、关键帧、复杂伪元素、实验性选择器和 SVG 深层规则移入职责明确的文件或 Tailwind 层；仅移动规则时应保持计算样式一致。
- [x] **N-07 外部资源产物检查**：禁止生产 CSS 出现未批准的 `http://` 或 `https://` 引用，确保离线约束不会再次退化。
- [x] **N-08 CSS 变量静态检查**：自动区分缺失变量、带回退变量和由 Vue 动态注入的变量。
- [x] **N-09 Tailwind 语义类检查**：禁止将 Tailwind 保留工具类名称用于纯业务语义，并检查构建产物中的意外工具类。
- [x] **N-10 文档状态修正**：在实际迁移完成前，不再以“Tailwind 已进入 Vite 构建管线”代表 Tailwind 样式约束已经完成。
- [ ] **N-11 非布局验收（部分完成）**：主题对比度、键盘焦点、低动画、构建产物及 Chromium/WebKit 功能已经验证；离线完整流程和 Firefox 仍未闭环。

## 3. 总体实施原则

- [x] 将 Tailwind CSS 作为页面和组件常规样式的首选实现方式，而不只是构建依赖。
- [x] 布局、尺寸、间距、排版、边框、阴影、颜色、交互状态和响应式变化优先使用 Tailwind 工具类。
- [x] 重复出现且语义稳定的控件样式可通过 Vue 基础组件封装，或在明确的 Tailwind `@layer components` 中使用 `@apply`，避免重新形成大型全局样式表。
- [x] 原生 CSS 仅保留设计令牌、字体声明、全局基础规则、关键帧、复杂伪元素、浏览器实验特性以及确有必要的 SVG 深层选择器。
- [x] 保留现有的运行时主题能力；迁移 Tailwind 时不得把动态主题色重新硬编码为固定颜色。
- [x] 采用移动优先的响应式实现，避免同一断点在文件多个位置反复覆盖。
- [x] 每一批迁移都应保持可独立构建、可测试、可回滚，不进行无法验证的一次性全量替换。

## 4. 必须整改项

### 4.1 让 Tailwind 成为实际样式实现层

- [x] 盘点 `main.css` 中可直接映射为 Tailwind 工具类的声明，至少包括 `display`、Grid/Flex、间距、宽高、边框、圆角、排版、对齐、阴影、透明度和常规状态样式。
- [x] 优先迁移页面外壳、顶部栏、侧栏/移动底栏、卡片、表单、按钮、筛选栏、列表、弹窗和统计布局。
- [x] 在迁移后的 Vue 模板中使用 `hover:`、`focus-visible:`、`disabled:`、`dark:`、`motion-reduce:` 和响应式变体表达状态，减少分散的手写状态选择器。
- [x] 对多处复用的按钮、表单控件、Surface、Modal、Pill、Tag 等样式建立基础组件或有限的组件层，不在各页面复制长串工具类。
- [x] 为动态主题建立 Tailwind 可识别的语义色彩令牌，例如页面背景、Surface、控件背景、主文字、次要文字、主色、副色、危险色、收入色和支出色。
- [x] 底层运行时 CSS 变量建议统一使用项目命名空间，如 `--rw-*`；再通过 Tailwind 4 的主题令牌映射为 `bg-*`、`text-*`、`border-*` 等语义工具类，避免变量自引用或与 Tailwind 内部令牌混淆。
- [x] 对确实依赖运行时值的少量位置使用 Tailwind 任意值语法或 Vue `style` 绑定，例如色相角度、图表宽度和标签树深度。
- [x] 迁移完成后，删除已经没有消费者的全局规则和依赖它们的补丁式覆盖。

### 4.2 解决 Tailwind 扫描产生的类名碰撞

- [x] 将统计 SVG 中的 `grid` 类改为不会与 Tailwind 工具类冲突的名称，例如 `chart-grid-line`。
- [x] 检查 `.container`、`.contents`、`.table`、`.ring`、`.filter`、`.transition`、`.sticky`、`.isolate` 等已进入构建产物的 Tailwind 工具类，确认是否来自真实模板意图。
- [x] 禁止把 Tailwind 保留工具类名称用于纯语义用途；新增 SVG、图表或状态类时使用清晰的业务前缀。
- [x] 增加构建产物检查，确保业务语义类不会因为 Tailwind 扫描而获得非预期布局属性。

### 4.3 修复未定义设计令牌

- [x] 定义当前缺失的 `--color-danger-soft`，并分别确认亮色和暗色主题下的对比度。
- [x] 修复浏览器能力警告使用未定义背景色的问题。
- [x] 修复“移除待添加标签”按钮悬停背景声明失效的问题。
- [x] 为 CSS 自定义属性增加静态检查，区分真正缺失的变量和由 Vue 动态注入的变量。
- [x] 清理长期未使用的颜色、图表饱和度和 Surface 变量，或补充其明确消费者。

### 4.4 满足离线运行约束

- [x] 移除生产样式中的 Google Fonts 远程 `@import`。
- [x] 不再保留 DM Sans 和 Noto Serif SC，改用无需额外下载的系统字体栈。
- [x] 在 Tailwind 字体令牌中配置系统字体回退。
- [x] 增加离线 E2E：拦截全部外部网络请求后，验证首屏、登录页、账本页和统计页仍能使用稳定字体与布局。
- [x] 增加生产产物检查，禁止 CSS 中出现未批准的 `http://` 或 `https://` 资源引用。

## 5. 样式结构调整建议

### 5.1 拆分全局样式职责

- [x] 将 `main.css` 收缩为清晰的 Tailwind 入口，只负责导入顺序和少量全局层。

- [x] 将实验性的 `appearance: base-select` 规则隔离并标明兼容性边界。

### 5.3 整理响应式策略

## 9. 完成定义

满足以下条件后，才可认为项目真正遵循了 Tailwind CSS 技术约束：

1. Tailwind 工具类或基于 Tailwind 的基础组件承担绝大多数常规界面样式。
2. 全局 CSS 不再承载各业务页面的完整布局和控件外观。
3. 保留的原生 CSS 均有明确职责，且不能用普通 Tailwind 工具类更清晰地表达。
4. 主题、响应式、交互状态和低动画模式通过统一令牌及变体实现。
5. 不存在 Tailwind 类名碰撞、未定义 CSS 变量、远程字体依赖或已知移动端裁切问题。
6. 构建、单元测试、跨浏览器 E2E、离线测试和可访问性检查全部通过。
