# 子标签实现与账本迁移

状态：已实现。更新于 2026-09-08。本文记录已确认方案的最终行为与回退方法。

## 使用方式

1. 标签页新增标签时，可指定父标签。空父级表示根标签。
2. 点击标签右侧“父级”可更改关系；界面排除自身和后代，Worker 再次校验防环及引用完整性。
3. 保存父级前会显示受影响记录数（包括历史和已删除记录）、全部有效支出的“包含标签”统计金额变化，并要求确认。主标签精确统计、直接选择、记账日期、资金流水不变。
4. 层级变更记录可在标签页展开查看。删除父标签时必须选择提升子标签到原父级，或移动到其他父级；不会级联删除后代。
5. 标签名称继续全账本唯一，按 NFKC、全半角和大小写无关规则查重；一个标签最多一个父标签，允许多层嵌套。

## 选择语义

- 用户直接选择的顺序存入 `explicitTagIds`；所有需要的祖先去重后追加至 `selectedTagIds`。
- 选择“娱乐 → 游戏付款 → 游戏内购买”中的末级，会自动选中两级祖先，标注“由子标签带入”并使用虚线边框。
- 默认主标签是第一个直接选择项，而非最上层祖先。
- 双击设置主标签不破坏直接选择顺序；双击隐式祖先时将其追加到直接选择序列，再设为主标签。
- 取消直接选择的主标签后，按直接选择顺序顺延。取消子标签不移除其他分支或直接选择仍需保留的祖先。
- 单击隐式祖先时列出带入它的直接子孙标签，明确确认“同时取消这些子标签”后才移除。
- 批量录入、已有账目标签编辑和资金更正共用 `TagSelection`。临时新建标签也能选择父级；取消不落库，提交只保留实际使用的临时标签及必要祖先。
- 系统内部 `__system__` 标记不进入用户标签树，也不能作为用户标签 ID。

## 统计与审计

- “包含子标签”筛选和统计使用祖先展开集合；一条支出同时选中两个同父级的子标签，父级仅计费一次。
- 增加“仅直接选择”筛选；明细区分直接与继承标签。
- 主标签统计默认保持精确口径。圆环图及主标签排行可以切换“按根级祖先汇总”；每笔支出只归入一个根级扇区，不把父子扇区相加。
- 统计下钻携带标签口径、币种和时间范围，避免汇总图与列表不一致。
- “包含子标签”排行中的不同标签可能共享支出，不能跨标签相加；界面明确标注。
- 更改父级时重算全部记录的派生标签，包含原始、更正、冲销、恢复和已删除记录。独立的 `hierarchyChanges` 保存关系变更，不新增资金流水。
- 删除标签只要求处理直接引用；隐式引用由子标签去向和祖先重算处理。直接引用列表包括历史版本，逐条或批量替换在一次 Worker 克隆操作和一次数据库事务内完成。

## 数据格式及升级过程

业务数据 `schemaVersion` 从 1 升为 2，与 `.rwbl` 加密容器 `version` 分开。压缩、KDF、AES-GCM、访问口令和紧凑外观元数据格式不变；yescrypt 不在此次范围内。

- 新建账本直接使用 schema v2。
- 本机 v1 解锁、v1 文件导入（含副本/替换）、v1 密文恢复，均进入同一显式升级确认流程。
- 先解密、完整校验，在内存深拷贝并验证迁移结果；预览阶段不改写账本密文或索引，也不开放旧账本查询会话。数据库存储区结构可在应用启动时升级。
- 现有标签保持 ID 和名称且全部成为根标签；每条旧记录的选择顺序原样复制为 `explicitTagIds`。不按标签名称猜测层级，不改变余额及原有统计。
- 确认框提供原始 v1 `.rwbl` 密文下载。取消即停止，不显示成功提示、不更改当前密文。
- 确认后重新压缩加密，再解密验证；验证成功后才以 IndexedDB 事务写入当前容器、索引、上一版本和独立升级备份。
- IndexedDB 版本升为 3，增加 `migration` 存储区。第一次升级的原始密文独立保留，普通编辑和后续恢复不会覆盖；设置页可再次导出。删除整个账本会一并删除它。
- 事务中的同步请求错误、空间不足或中断都会回滚，不留下半写入的当前数据或备份。
- schema v2 再打开不会再次升级。未知 schema 明确拒绝，损坏引用和成环关系拒绝导入或恢复。

## 备份与回退

升级后的账本无法用原 schema v1 客户端读取。旧客户端原有严格的 schema 检查会拒绝 v2；不得简单把 schema 数字改回 1，这会丢失层级语义。

需要回退时，在升级确认框或设置页导出“v1 升级前备份”，再用旧版客户端导入。该快照不包含升级后的新增或修改记录；回退前也应额外导出当前 v2 文件。账本副本的原始升级备份保留原文件的 ID 与名称。

本次也升级了 IndexedDB 数据库版本，旧客户端无法直接打开已升级的本机数据库。回退请使用独立浏览器配置或其他隔离的站点存储环境导入 v1 备份，不要直接清空当前站点数据尝试降级。

上一版本恢复和独立升级备份是两个机制：前者用于最近一次写入回退，后者用于恢复最初的 v1 数据。关闭页面、取消升级或写入失败无需手动恢复旧密文。
